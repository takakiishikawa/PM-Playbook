## 原則

- 悪い情報ほど、責任者に早く正確に伝える。トラブルは一次対応の速さが重要。
- 調査や社内会議よりも先に、ユーザーへの報告と対応を怠らない。ユーザーへの影響の最小化を優先する。
- コンティンジェンシープランは、誰もが対応できる手順として策定する。

## コンティンジェンシープランとは

障害やトラブルが起きたときの対策。バックアップや代替手段を示し、不測の事態に迅速に動けるようにする。

## 準備しておくこと

| 項目 | 内容 |
| --- | --- |
| 責任者と連絡先 | 誰に連絡し、誰が判断するか |
| 作業の優先順位と手順 | 何から、どう対応するか |
| リソース | 人員、機材、設備、情報の配置と使い方 |
| 判断基準 | 経過の基準や、意思決定のための情報 |
| 情報の収集・評価・伝達 | 手段をどう確保するか |
| 効果の検証方法 | 対応策が効いたかをどう確かめるか |
| 報告方法 | 現状報告や復旧状況の報告のしかた |

## 発生したときの情報共有

- **最新状況を明確にする**：第一報、第二報と、進行形の情報の「現在地」を正しく共有する。
- **悪い情報ほど早く上げる**：すぐ責任者まで報告が届く仕組みを用意しておく。
- **ユーザーへの影響を最小化する**：何よりも先に、ユーザーへの報告と対応を行う。
