## 原則

- <Mark>**「とりあえず集める」は非効率。立てたい仮説や解きたい課題から逆算して、必要なデータを洗い出す。**</Mark>
- データはインサイトを導く素材。正確性と網羅性が分析結果の質を決める。
- PMがSQLを使えると、短期間でユーザーの解像度を上げられる。最低限STEP2、できればSTEP3を目指す。

## データ収集・整理の流れ

<Steps>
  <Step title="課題（ゴール）を明確にする">何のためにデータを集めるのか</Step>
  <Step title="必要なデータを特定・設計する">ゴールに必要なデータと収集方法を決める</Step>
  <Step title="集める">ツールやインタビューなど手法を組み合わせる</Step>
  <Step title="整理・クリーニングする">欠損や誤りをチェックし、整形・統合する</Step>
  <Step title="分析する">仮説やインサイトを導く</Step>
  <Step title="意思決定・施策立案">具体的な施策を考えて実行する</Step>
</Steps>

<Caution>整理が不十分だと、誤ったデータや欠損が分析結果を誤らせる。後工程で「必要なデータがなかった」と気づくと、後戻りで時間とコストがかかる。</Caution>

## 必要なデータを決める

- **課題を明文化する**：例「サイトの離脱率が高い」。仮説があると見るべき視点が定まる（例：客単価が下がったのは、新規ユーザーが増えて購買が一度きりだからではないか）。
- **指標を決める**：ECなら新規ユーザー数、リピート購入率、平均購買単価。
- **形式を考える**：数値、テキスト、画像、ログ。
- **範囲を決める**：期間、地域、対象ユーザー層。

## どこから集めるか

| 種類 | 例 |
| --- | --- |
| 社内データ | CRM、会計、販売管理などにすでに蓄積されたデータ。まず最初に確認する |
| 一次データ | アンケートやインタビュー。仮説検証に必要な意見や感想を補う |
| オンラインデータ | Web解析ツール、SNSや口コミ（テキストマイニングで評判を分析）、国や自治体のオープンデータ |
| 二次データ | 調査会社のレポートや購買データ（自前の調査コストを省けるが条件を指定できないこともある）、業界団体の資料 |

## データを整える

| 作業 | 内容 |
| --- | --- |
| フォーマットの統一 | 日付の表記ゆれ、文字列で保存された数値、「関東」と「首都圏」のようなカテゴリ名の混在をそろえる |
| 欠損値の処理 | 未回答や途中で切れたログを、統計的に補うか分析から除くかを決める |
| 異常値の検出 | 「1日1億アクセス」のような明らかにおかしい値は、障害や入力ミスが原因のことが多い。原因を探り、修正するか対象外にする |
| 集計の粒度 | 日次・週次・月次など粒度をそろえておく |

データ品質は、完全性（欠損の少なさ）、一貫性（ソース間で値が食い違わない）、正確性（入力ミスやバグの少なさ）、信頼性（ソースや取得過程が信用できる）で評価する。

| 仕組み | 役割 |
| --- | --- |
| ETL | 異なるシステムから抽出し、変換し、データベースやDWHに格納する。定期的な取得と整形を自動化しやすい |
| BIツール | ドラッグ&ドロップでレポートやダッシュボードを作れる。非エンジニアでも扱いやすく、異常値の発見にも役立つ |
| DWH | 大量のデータを長期間蓄積し、横断的に分析する基盤 |

## 分析に入る前に

- **全体像をつかむ（探索的分析）**：可視化や単純集計で傾向と分布を見る。気になる異常値や意外なパターンはメモする。
- **相関を確かめる**：どの指標同士が相関しているかから仮説のヒントを得る。
- **分析の問いを決める**：「どの顧客層が最もリピートしやすいか」「伸び悩みは価格か品ぞろえか」。問いに合った手法を選ぶ。
- **因果を検討する**：相関だけでなく、季節要因か施策の効果かなど、背景を踏まえて整理する。

## SQLのステップ

| ステップ | できること |
| --- | --- |
| 1. データ構造を理解する | データベースとテーブルの概念。SELECT、FROM、LIMITで各テーブルを抽出する |
| 2. 簡単な集計ができる | WHERE、GROUP BY、ORDER BYで絞り込みと並べ替え。COUNT、SUM、AVGで集計。JOINで複数テーブルから抽出する |
| 3. 複雑な集計ができる | サブクエリ、一時テーブル、CASEやIFの条件分岐、ウィンドウ関数 |
| 4. 大量データを効率的に扱う | インデックス、パフォーマンスチューニング、ストアドプロシージャ、データベース設計と正規化 |

分析で必要になる操作は、条件による絞り込み（「今月の」「商品Aを購入した」）、分類・グルーピング（「カテゴリ別に」「ユーザーごとに」）、集計（数え上げ、合計、平均）、複数テーブルの結合。たとえば「7月によく売れた商品カテゴリ」は、注文・注文明細・商品・カテゴリのテーブルを結合し、7月で絞り込み、カテゴリ別に販売数量を合計して多い順に並べる。

<Note title="ツール">BIツールの例にRedashがある。オープンソースで無料、ダッシュボード機能があり、さまざまなソースから抽出できる。</Note>
