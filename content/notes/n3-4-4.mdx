## 原則

- 質問はシンプルに、1つの問いに1つの内容。
- 偏りのない表現にする。誘導尋問に注意する。
- 想定していない答えや新しいインサイトが得られるよう、あえてオープンエンドの問いも用意する。

質問設計の目的は3つ。適切なインサイトを得るため、限られた時間を最大限に活用するため、ユーザーとの関係構築を円滑に進めるため。

## プロセス：質問を設計する

## 質問の基本

### オープンとクローズドの使い分け

| | オープンクエスチョン | クローズドクエスチョン |
| --- | --- | --- |
| 定義 | 回答者が自由に答えられる | 回答の選択肢が限られる |
| 例 | 普段、どのようにこのサービスを使っていますか？ | この機能を週に何回使っていますか？ |
| メリット | 回答の幅が広がり、予期せぬ情報を得やすい | 定量的で比較しやすい。短時間で要点を押さえられる |
| デメリット | 漠然としすぎると回答が散漫になる。答えにくいと感じる人もいる | 深い洞察や想定外の情報を拾いにくい |

### 1つの問いに1つの内容

| 悪い例 | 良い例 |
| --- | --- |
| 新機能のUIについてどう思ったか、使い勝手はどうか、改善点はあるか教えてください | 1. 新機能のUIを見た第一印象はいかがでしたか？　2. 実際に使った際、操作性はどう感じましたか？　3. 改善できるとしたら、どんなポイントを直すと良いと思いますか？ |

### 偏りを減らす

| 避けること | 例 |
| --- | --- |
| 誘導的な表現 | 「皆さん魅力的だと考えているようですが、どう思いますか？」「この機能、便利ですよね？」 |
| 肯定・否定のニュアンスが強すぎる | 「それはいいですね」と肯定しすぎると、否定的な意見を出しづらくなる |
| 期待させすぎる | 「めちゃくちゃ便利になりますよ」と前振りすると、良い面ばかり考えてしまう |
| ペルソナへの固執 | ペルソナはあくまで典型像。予想外の意見や多様性を柔軟に受け止める |

良い聞き方の例：「率直に、デザインに対してどのような印象を受けましたか？」

## 質問の順序

| 段階 | 内容 | 例 |
| --- | --- | --- |
| 1. ウォーミングアップ | アイスブレイク、世間話 | 今日はどのようにここまで来られましたか？ |
| 2. コンテキストの把握 | バックグラウンドや現状 | 現在どんなサービスを利用していますか？ |
| 3. 核心の質問 | 目的に直結する内容。使い方やニーズを深掘りする | このアプリのデモを見た第一印象は？ 使いにくい点は？ |
| 4. まとめ・フィードバック | 今後の期待や要望、話し足りないこと | 追加であったら便利な機能はありますか？ |

## 深掘りの質問

- 再質問：「それは具体的にどんな場面で感じましたか？」「もう少し詳しく教えていただけますか？」「そう思われたきっかけや背景はありますか？」
- 5Why：「なぜそう思ったのか」を繰り返し、根本的な課題や本音に近づく
- 感情を聞く：「そのときどう感じましたか？」「ストレスや不安はありましたか？」
- エピソードを引き出す：「直近で『これは面倒だったな』と思ったことを教えてください」
- サイレント：あえて少し沈黙を作ると、補足や話し足りないことを話してくれる

## ペルソナから質問を作る

ペルソナに描かれた情報を洗い出し、「何を知りたいか」「どこが未知なのか」を明確にする。「知りたい内容」と「その理由」をセットで書く。

| ペルソナの特徴 | 質問の組み立て方 |
| --- | --- |
| 行動パターン（週に3回は料理をする） | その行動のモチベーションや課題を探る |
| 心理的特徴（節約志向が強い） | コストパフォーマンスや価格比較のやり方を深掘りする |
| 利用シーン（通勤中にアプリを見る） | 移動時間のどこに不満や潜在ニーズがあるかを探る |

<Note title="目安">得たい情報の分類例（レシピアプリ）：現在の課題・不満、情報収集の流れと習慣、改善・アイデアのニーズ、使い始める・やめる心理的プロセス、料金・コストへの感覚。</Note>

## 注意点

1. 目的とのズレ
2. 専門用語の多用
3. 質問の意図を説明しすぎない（説明しすぎると恣意的になる）
4. 沈黙を恐れない
5. オンラインと対面の違いを意識する

## ヒアリング後

1. データを整理・可視化する：テキストマイニングやマインドマップで整理し、繰り返し出たキーワードから共通点を探す
2. 仮説と比べて再検証する：どこが合い、どこが違うかを確かめ、外れていれば方向転換する
3. 次の質問や対象を検討する：深掘りが必要なテーマや別のペルソナが見えたら、次のヒアリングを設計し直す

共有するときは、ペルソナと主要なインサイトを分かりやすくまとめ、具体的な改善案と次のアクション（次回のヒアリングやABテスト）まで示す。エンジニア・デザイナー・マーケティングなど部門横断で議論する場を設ける。
