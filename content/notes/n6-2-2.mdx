## 原則

- KPIは、課題が解決された状態から逆算して決める。
- 解くべき課題を理解できていないと、適切なKPIは設定できない。
- 作り慣れないうちは、SMARTに沿って一つずつ考える。

## SMART

| 要素 | 内容 |
| --- | --- |
| Specific（具体的） | チームの意識がそろい、行動を取れるようになる。最も重要 |
| Measurable（測定可能） | 定量または定性で、達成したかどうかの基準を作る |
| Achievable（達成可能） | 実現できる範囲にすると、具体的なアクションを決めやすい |
| Relevant（関連性がある） | 事業KPIやプロダクトロードマップに紐づいている |
| Time-bound（期限がある） | 期間を区切り、定期的に達成状況を評価して見直す |

| 要素 | 例1：定量（チャット機能） | 例2：定性（チャット機能） |
| --- | --- | --- |
| S | ユーザーエンゲージメントを向上させる | ユーザー満足度を向上させる |
| M | 利用者数と1カ月あたりのチャット回数を測る | フィードバックやレビューで満足度を評価する |
| A | 利用者数が現ユーザーの30%、チャット回数が月平均50回 | 満足度が5点満点で4.5 |
| R | エンゲージメントに直接関わり、使いやすさや満足度に影響する | 継続利用や口コミにつながる |
| T | リリース後3カ月 | リリース後3カ月 |

## 逆算で決める

「そのために何が必要か」を繰り返す。

## KPIには大きさがある

| 大きさ | 決め方 |
| --- | --- |
| 大 | 中長期のプロダクトロードマップから逆算する |
| 中 | ロードマップ達成に必要な機能をリリースし、機能ごとに決める |
| 小 | キャンペーンや企画、機能改善ごとに、課題を解決できているかを測る |
