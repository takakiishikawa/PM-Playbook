## 原則

- <Mark>**「AIを使って何かすごいことをしたい」という漠然とした動機ではうまくいかない。解決したい課題と求める成果を先に定義する。**</Mark>
- AIはデータがなければ正しく学習できない。データが偏っていれば、判断も偏る。
- 自社が解決したい課題に適したAIの種類や手法を選ぶ。

## AIの種類

| 種類 | 仕組み | 特徴 |
| --- | --- | --- |
| ルールベース | 「もしAならばBをする」という条件と動作を大量に定義する | ルールがはっきりした領域では高度な判断ができるが、ルール外のケースに対応できず、ルールが増えるほど管理が複雑になる |
| 機械学習 | データからパターンを学習させる | 教師あり学習（正解ラベルつきのデータで学習。例：スパム判定）、教師なし学習（ラベルなしでパターンを発見。例：顧客のクラスタリング）、強化学習（報酬を最大化するよう試行錯誤。例：囲碁AI、自動運転） |
| 深層学習 | 脳の神経細胞を模したニューラルネットワークを多層に重ねる | 人が特徴量を細かく設計しなくても、自ら学習して高精度に識別・予測できる。一方でモデルや計算量が大きく、導入には工夫が要る |

近年のAIブームを牽引しているのは機械学習と深層学習。インターネットの普及で膨大なデータが手に入り、GPUなどの高速計算環境が整ったことが背景にある。

| 用途 | 例 |
| --- | --- |
| 画像認識 | 画像分類、物体検出。自動運転、監視カメラの解析、画像検索 |
| 自然言語処理 | 文章分類、翻訳、生成、質問応答。チャットボット、SNS投稿の解析 |
| 音声認識 | 音声のテキスト化、感情分析。文字起こし、コールセンターの会話解析 |
| 強化学習 | ゲーム攻略、ロボット制御 |
| レコメンド・パーソナライズ | ECの商品推薦、動画配信のコンテンツ推薦 |

## AIが動くまで

<Steps>
  <Step title="データを集めて準備する">行動履歴、画像、テキストなどを集め、欠損値や異常値を処理する</Step>
  <Step title="学習用と検証用に分ける">例：訓練データ80%、検証データ20%</Step>
  <Step title="モデルを選び学習させる">アルゴリズムを選び、誤差が最小になるよう最適化する</Step>
  <Step title="評価してチューニングする">検証データで精度を測り、改善する</Step>
  <Step title="推論し運用する">新しいデータで予測や分類を行う。リリース後も再学習やデータの追加で精度を保つ</Step>
</Steps>

## 導入時に意識すること

| ポイント | 内容 |
| --- | --- |
| 目的と課題の明確化 | 解決したい課題と求める成果を定義する |
| データの質と量 | 特に深層学習では大量の高品質なデータが要る |
| 性能評価の指標 | うまく機能しているかを判断する指標を決める。精度、再現率、適合率など |
| 透明性と説明責任 | ヘルスケアや金融など影響が大きい分野では、なぜその判断をしたかを説明できないと信頼を得にくい |
| 法規制・倫理 | 個人情報が含まれていないか、同意のプロセスは適切か、差別や偏見を助長していないか |

## PMが押さえる可能性と限界

| 可能性 | 限界 |
| --- | --- |
| 大量データからパターンを自動で抽出し、人が気づけない洞察を得られる | データや学習方法によっては偏った判断をする |
| 推論が高速で、リアルタイムのサービスにも使える | 学習したタスクや領域を外れると、途端に精度が落ちる |
| 特定の領域では人の精度を超える | モデルが複雑になると、学習や運用のコストが高くなる |
| | 判断がブラックボックスになり、説明責任が問題になることがある |
