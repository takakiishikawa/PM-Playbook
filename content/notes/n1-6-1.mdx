## 原則

- <Mark>**事業計画からではなく、ビジネスモデルの探索から始める。製品ではなく、顧客開発を軸に仮説を検証する。**</Mark>
- 満足のいく成果が得られなくても、必ず意思決定まで行う。

## リーン・スタートアップのサイクル

リーン（無駄がない）とスタートアップ（起業・新規事業）を組み合わせた言葉。

<Steps>
  <Step title="仮説">顧客ニーズの仮説を、売れるかどうかの価値仮説と、事業が伸びるかの成長仮説の2軸で立てる</Step>
  <Step title="構築">必要最小限の機能を備えたMVPを作る</Step>
  <Step title="計測">MVPをリリースし、想定顧客のフィードバックとデータを集める</Step>
  <Step title="学習">計測結果と仮説を照らし合わせ、課題と原因、改善方法を探る</Step>
  <Step title="意思決定">改良や方針転換・軌道修正を決め、次のサイクルに入る</Step>
</Steps>

| | 従来型 | リーン・スタートアップ |
| --- | --- | --- |
| 戦略 | 事業計画が起点、実行を重視 | ビジネスモデルが起点、仮説を重視 |
| 開発 | 製品マネジメント。ウォーターフォールで、事前に仕様を固める | 顧客開発。オフィスを飛び出して検証し、アジャイルでやり直しを重ねながら作る |
| 組織 | 職能別組織。経験と実行能力で採用する | 顧客対応チームとアジャイル開発チームが主体。学習意欲・柔軟性・スピードで採用する |

試行とフィードバックを繰り返し、有効なビジネスモデルが見えてから実行に重点を移す。

## リーンスプリントの5ステージ

「連携 → 発散 → 収束」を繰り返し、個人の考えと共同作業のバランスを取る。

1. 問題を明らかにする
2. ソリューションを定義する（発散）
3. ソリューションを一覧にする（収束）
4. ソリューションを検証する（発散）
5. ソリューションを決定する（収束）

## ボトルネックを見つけて改善する

プロダクトを成長エンジンとして、ユーザー獲得 → 定着 → 収益化 → 紹介の流れのどこに最も弱いつながり（ボトルネック）があるかを見つける。

| 段階 | 問い |
| --- | --- |
| 獲得 | どうやってユーザーを特定するのか |
| 定着 | 最初に経験する価値は何か。何度も使ってもらうには何が必要か |
| 収益化 | 価格モデルは何か |
| 紹介 | 紹介してもらうポイントは何か |

ボトルネックはプロセスに沿ったインタビューで見つける。顧客情報の収集 → 課題発見の文脈設定 → ソリューションの説明 → 価格の検証 → 今後の協力・紹介依頼 → 結果の文書化の順に進めると、アーリーアダプターの特定、ソリューションと価格の検証、ナレッジの蓄積ができる。
