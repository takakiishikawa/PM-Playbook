## 原則

- 目的に対してどの軸でクロス集計すれば仮説を評価できるかを、逆算して調査票を設計できる状態をまず目指す。
- 可視化とプレゼンは、情報（Information）を知識（Knowledge）に変える作業。背景を知り、文脈をもって事実を伝える。
- 1つのチャートに1つのメッセージ。

## 単純集計とクロス集計

| 集計 | 内容 |
| --- | --- |
| 単純集計 | 質問ごとの回答者数（n数）と回答比率や平均値。成果物は単純集計表（GT表）。まずこれで全体感をつかむ |
| クロス集計 | 単純集計の値を、性別・年齢・地域や他の質問と掛け合わせて深掘りする。属性クロスと設問間クロスがある |

国内企業では横%表、外資系企業では縦%表が多く使われる傾向がある。

<Steps>
  <Step title="全体傾向をつかむ">クロス集計表の「全体」の行を横方向に眺め、結果を大枠でつかむ</Step>
  <Step title="比較して相対的な差を見る">最も高い・低い項目、全体との差が大きい選択肢や分析軸を探す</Step>
</Steps>

### 軸を加工する

- 複数の選択肢をまとめる。例：5段階評価をまとめて「満足計」を作る。数値回答を平均以上・以下に分ける
- 複数の設問を掛け合わせる。例：性別と年代を組み合わせて性年代の軸を作る

### 軸の選び方

分析は因果関係を推測する目的で行うことが多いので、原因か結果のどちらかに注目して軸を選ぶ。

| 注目 | 軸の例 |
| --- | --- |
| 原因 | 属性（性別、年代、職業）、デバイスの保有状況、食習慣 |
| 結果 | サービスの利用状況、健康状態 |

## アンケートで測る指標

### 認知率・利用率・浸透率

| 指標 | 内容 |
| --- | --- |
| 認知率 | ターゲットのうちサービスを知っている人の割合 |
| 利用率 | 調査時点で利用している人の割合 |
| 浸透率 | 利用したことがある・利用している人の割合。過去に使って今は使っていない人も含む |

認知は2つに分かれる。手がかりなしで思い浮かぶ純粋想起は、ブランドの強さを示し、自由記述で聞く。手がかりを与えて思い出す助成想起は、認知度全体を測るのに使い、選択肢から選んでもらう。

### NPS

「この商品・サービスを友人や同僚に薦める可能性はどのくらいありますか」に0〜10で答えてもらい、推奨者の割合から批判者の割合を引く。顧客ロイヤルティを測り、支持する層と離反しそうな層を特定できる。

NPSに加えて機能や要素ごとの満足度を聞くと、NPSの向上にどの要素が重要か、競合とユーザー評価がどう違うかを分析できる。

### CES（カスタマーエフォートスコア）

サービスを使うとき、顧客自身がどれほど努力を要したかを示す。「この商品・サービスを利用する際、努力が必要でしたか」に答えてもらい、「まったく努力しなかった」側の上位2つの割合から、「非常に努力した」側の下位3つの割合を引く。

- 顧客が感じる不満を数値化でき、オンボーディングでも重要な指標になる
- 定期的に測ると、顧客体験の改善状況を評価できる
- 体験直後の記憶が鮮明なうちに測る。自動化の仕組みを作っておくとよい
- 評価できるのは顕在化した不満で、潜在的な改善点の把握には不十分

## 可視化する

定量分析は、軸間の「比較」、全体と一部の「構成」、時間軸の「変化」で表す。

| アンチパターン | 対処 |
| --- | --- |
| 1チャートに複数のメッセージ | 認知負荷が高い。解釈が定まっていないなら数表のまま載せて解釈の余地を残し、ストーリーが定まっているならメッセージごとにチャートを分ける |
| 色分けの乱用 | 伝えたいことが埋もれる。強調すべき箇所だけ色をつける |
| 途中で切ったグラフ | 差が実際より大きく見える |

## 伝える

- **1スライド1メッセージ**：タイトル、メッセージ、グラフタイトル、ボディ、出典で構成する。
- **ピラミッドストラクチャー**：結論を論拠と詳細で補強する。相手の視点や理解度に合わせて説明範囲を調整できる。
- **相手に合わせた粒度**：多様なステークホルダーに適切な粒度で伝え、意思決定と合意形成につなげる。
