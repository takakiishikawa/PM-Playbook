## 原則

- コアバリューは「なぜ作るのか」と価値の追求。
- 担当プロダクトに合ったプロダクトマネジメントの体系を作る。体系があれば、個々の部分は自然と必要十分になる。
- 大人数の会議より、少人数や1on1で話す。
- 苦手な場面では頑張って溶け込もうとせず、事前の準備と回復の時間で補う。

## 強み

<Cards>
  <Card label="本質を問う">論理的思考とBiz経験を活かし、なぜ作るのか、本当の価値は何かを問い続ける。ユーザー課題の根本原因を分析し、改善をリードする</Card>
  <Card label="体系を作る">コアバリュー・KPI・長期ロードマップを磨き続ける。入り口から出口までのチームのプロセスを整え、良い設計と継続的なリファクタリングを支える</Card>
  <Card label="少人数で深く話す">1対1の対話が得意。ステークホルダーやエンジニアとは、少人数や1on1で議論する</Card>
</Cards>

## プラクティス

| 領域 | やること |
| --- | --- |
| 時間管理 | 見積もりは1.5倍で置く。進捗管理はBrSEに任せる |
| 完璧主義の制御 | 常に必要十分を基準にする。80%の段階で一度レビューに出す |
| エネルギーの保全 | 午前のDeep Workを守る（Slackを切る）。繰り返し作業や感情的なやりとりはBrSEに任せる。ノイズキャンセリングを使う |
| Deep Thinking | 週の10%を、ユーザー・プロダクト・価値について考える時間にあてる |

## コミュニケーション

| やる | やらない |
| --- | --- |
| 少人数のランチで、仕事も含めて積極的に質問する | 集団の会話に溶け込もうと頑張る |
| 親しいBrSEに、自分のことを話しておく | 誕生日やお別れを無理に祝おうとする |
| 相手の感情は、感じ取ろうとするより聞いて確かめる | 疲れているのに集団の場に残り続ける |
| 疲れたら、1人の時間をとる | |
