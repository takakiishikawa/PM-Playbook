## 原則

- ユーザーは自分の欲求や問題点を正確に把握しているとは限らない。要望の「本当の理由」に気づかなければ、本質的な課題解決にはつながらない。
- 大事なのはヒアリングの「量」ではなく「質」。小さな手がかりを見逃さず、繰り返し問いかける。
- インサイトは固定的な答えではなく、ユーザーや環境の変化に合わせて変わる「生きた仮説」。

## データ・ファクト・インサイト

| | 内容 |
| --- | --- |
| データ | 定量的に集めた数値や統計、観測されたログ |
| ファクト | データを整理・分析して得た客観的な事実 |
| インサイト | 事実の背景にある、ユーザーの感情や欲求、行動のトリガーを推測・洞察した結果 |

| データ・ファクト | インサイト |
| --- | --- |
| フィットネスアプリの継続率が低く、3日坊主が多い | アプリを開く前の「やる気のハードル」が高い。仕事や学業の合間にわざわざ記録するのが面倒 |
| オンライン学習の利用時間が1か月で大幅に減り、「時間がない」という回答が多い | 本音は「学習の手応えがなく、習慣化できず楽しくない」。進捗が見えないとモチベーションが続かない |

インサイトは、ユーザーが自覚していない深い課題やニーズに近づく手がかりになり、新規サービスの差別化や、満足度を高める指針になる。

## インサイトが生まれる流れ

1. 観察：インタビュー、アンケート、行動データでユーザーの姿を捉える
2. 分析：フレームワークで情報を絞り込み、関連性やパターンを探す
3. 深い洞察：パターンをさらに掘り下げる。「主観的な思い込み」と「合理的な推論」を混同せず、裏付けとなるエビデンスを集め直す

<Caution>先入観による恣意的な結論、部分的な声の過度な一般化、仮説検証をしないまま施策に落とし込むことに注意する。</Caution>

## フレームワーク

| 手法 | 内容 |
| --- | --- |
| 5Whys | 発言や行動に「なぜ？」を繰り返す |
| KJ法（親和図法） | 意見をカードに書き出し、似たものをグループ化してラベルを付け、上位グループへまとめ、関係性を図解する |
| エンパシーマップ | Think（考えていること）・Feel（感じていること）・See（見ているもの）・Say/Do（言っていること・していること）・Pain（痛みや不満）・Gain（得られているメリット）に整理する |
| カスタマージャーニーマップ | 認知 → 検討 → 購入 → 利用の段階ごとに、行動と感情の上がり下がりを可視化する |
| ペルソナとシナリオ | 典型的なユーザー像と、その人が体験するストーリーを描く |
| テーマ分析 | データを熟読し、コードを付け、テーマを探し、見直し、定義して名前を付ける |

## プロセス：インサイトを抽出する

<Steps>
  <Step title="仮説を作り設計する">ゴールを明確にし、仮説を作り、ヒアリング項目を整理する</Step>
  <Step title="5Whysで聞く">リラックスできる雰囲気で聞き役に徹し、「なぜ」を重ねる</Step>
  <Step title="KJ法で整理する">付箋に書き出し、グルーピングとラベリングで関係性を可視化する</Step>
  <Step title="エンパシーマップを作る">Pain（どんな苦痛を感じているか）とGain（どんな期待や喜びを求めているか）に注目する</Step>
  <Step title="インサイトを言語化する">「○○だから△△したいと思っている」「実は□□という欲求を持っている」と書き、施策アイデアにつなげる</Step>
</Steps>

<Note title="補足">事例：在宅勤務者10名の「オンライン会議が多すぎてしんどい」に5Whysを重ねると、「孤立を避けたくて会議を増やしているが、そのせいで疲労も増えている」という矛盾が見えた。インサイトは「孤独を感じたくないが、仕事は邪魔されたくない。雑談のような気軽なコミュニケーション手段を求めている」。</Note>

## 定性データの整理

<Steps>
  <Step title="収集と管理">一次情報を、後から追跡できる形でまとめる。個人を特定できる情報は匿名化する</Step>
  <Step title="文字起こし">自動ツールを使っても必ず校正する。話し手を区別し、気になる点に印を付ける</Step>
  <Step title="コード化">発言の断片ごとに意味のまとまりを見つけ、ラベル（コード）を付ける</Step>
  <Step title="カテゴライズ">共通点のあるコードをまとめ、上位のテーマに再編する</Step>
  <Step title="要約と再構築">発言の環境・利用シーン・感情の変化など、文脈を補って整理する</Step>
</Steps>

| コード化の方法 | 内容 |
| --- | --- |
| オープンコーディング | 事前のカテゴリーにとらわれず、テキストからそのままコード化する |
| アプリオリコーディング | 事前に決めた分析枠組みに従って分類する |

<Note title="目安">カテゴリーを横断してテーマを探す。「UIが分かりづらい」「初期登録が煩雑」「ガイドが不足」は「学習コストが高い」というテーマにまとまり、「初回ガイドを充実させる」という施策につながる。タグの例は「課題」「要望」「アイデア」「感情表現」「環境要因」。</Note>

### インサイトを探す視点

- 繰り返し登場するキーワードや感情。言葉に出さなくても、表情や仕草から繰り返しうかがえる感情
- 矛盾やギャップ：言葉ではこう言っているが、行動では違うことをしていないか
- 背景や文脈との関連づけ
- 本当に求めている価値は何か、実際に何に最も困っていたか、気づいていない潜在ニーズはないか

<Caution>定性データは解釈の余地が大きく、分析者の先入観が入りやすい。できれば複数人でコーディングし、レビューする。可視化そのものを目的にしない。</Caution>

## インサイトの検証と優先度

思い込みやバイアス、ユーザーの回答の変化、状況の変化のリスクがあるため、インサイトは定性調査・定量調査・プロトタイプやMVPのテストで検証する。一部だけ裏付けられた、反対のデータが出た、新たな仮説が生まれた場合は、インサイトを組み立て直す。

複数のインサイトがあるときは、重要度（ユーザーにとっての切実さ）、緊急度（今すぐ取り組むべきか）、実現可能性（リソース・技術・組織の制約）で優先度をつける。

<Steps>
  <Step title="一覧にする">整理したインサイトを並べる</Step>
  <Step title="基準を合意する">優先度の判断基準をチームで決める</Step>
  <Step title="スコアリングする">各インサイトを評価し、順位を仮決定する</Step>
  <Step title="調整して合意する">最終的な順位を決める</Step>
  <Step title="アクションに落とす">上位から施策にし、効果検証を回す</Step>
</Steps>

<Caution>上位のインサイトだけに目を奪われて他を検討しない、組織の政治的・感情的な理由で順位が決まる、目的や戦略との整合を忘れる、に注意する。</Caution>
