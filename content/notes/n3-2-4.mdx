## 原則

- ユーザーの声を表面的に受け取らない。表層的なペインの背後にある、根本的なペインを探す。
- 特に重要なのは、ユーザー自身が意識していない問題や、言葉と行動のギャップ。それこそが真のユーザーペインになりうる。
- ペインは見つけて終わりではない。そこからがプロダクト改善の出発点。

## ユーザーペインとは

ユーザーが抱えている課題や困りごと、望ましい状態に至れていない原因。たとえば、エクセルファイルでの情報共有の難しさ、ネットショップで配送日時を指定できないことなど。

<Cards>
  <Card label="顧客満足度の向上">ペインを解消すると利便性や満足度が高まり、リピーター獲得や口コミにつながる</Card>
  <Card label="差別化の源泉">似たサービスが多い中、具体的なペインを捉えて解決できれば競合優位性を築きやすい</Card>
  <Card label="方向性が明確になる">ペインを起点にすると、何を優先するべきかが明確になり、開発の無駄を防げる</Card>
</Cards>

### 人間の行動と心理から生まれるペイン

<Cards>
  <Card label="面倒くさい">人はできるだけ少ない労力で済ませたい。手間がかかる作業に不満が生まれる</Card>
  <Card label="不確実性を嫌う">配送日時や料金が分からない、手続きの結果が分からないと、心理的な抵抗感が生まれる</Card>
  <Card label="コミュニケーションの不一致">問い合わせに時間がかかる、チャットボットが意図した返答をしないなど、かみ合わないときにペインが顕在化する</Card>
</Cards>

### ペインの例

| toC | toB |
| --- | --- |
| ECサイトで配送先を毎回入力する、返品や交換が複雑 | 複数ツールの併用で、どの情報がどこにあるか分からない |
| オンライン会議ツールの機能がごちゃごちゃしていて戸惑う | 機密情報の扱いや権限設定が分かりにくい |
| SNSの情報や通知が多すぎて疲れる、プライバシー設定が複雑 | 導入後のサポートが不足し「使いこなせない」 |

## ペインを見つける手法

| 手法 | ポイント |
| --- | --- |
| ペルソナ設定 | ターゲットとなるユーザー像を、性別・年齢・職業・行動パターン・趣味嗜好まで具体的に描いた架空の人物像 |
| カスタマージャーニーマップ | 認知・検討・購入・利用継続の段階ごとに、困っていることはないかを洗い出す |
| 5Whys（なぜなぜ分析） | 表層的なペインに「なぜ」を繰り返し、原因を掘り下げる |
| インタビュー | オープンクエスチョンを多用し、流れは柔軟に。意外な方向の話を臨機応変に掘り下げる |
| アンケート | 「はい・いいえ」だけの設問では背景が見えない。自由回答欄を設け、募集チャネルを複数にしてサンプルの偏りを防ぐ |
| ユーザビリティテスト | 操作ログや録画で定量・定性の情報を得る。「あれ、どうやるんだろう」というつぶやきはペインの断片。途中で質問せず観察し、終了後に深掘りする |
| 行動ログ分析 | カート放棄率や離脱率から仮説を立てる。理由まではデータで分からないため、定性調査と組み合わせる |

### 例：5Whysで掘り下げる

「ショッピングサイトで返品のステップが分かりにくい」という不満に対して、なぜを繰り返す。

1. 返品フォームにたどり着くまで3クリック必要
2. 返品フォームを管理画面の奥深くに置いている
3. 通常の問い合わせと同じフォームにまとめている
4. 問い合わせ数を管理しやすいように、1つの仕組みにしている
5. 過去の担当者がそこまでUI/UXを考慮していなかった

## 表層的なペインと根本的なペイン

| 表層的なペイン | 根本的なペイン |
| --- | --- |
| ユーザーが直接感じる問題や不満。例：UIが分かりにくい、操作が直感的でない | 背後にある本質的な問題。例：業務フローとシステム設計がずれている、タスクや権限の範囲があいまいで入力すべき情報が明確でない |

背景要因を深掘りすると、本質的な問題解決、革新的なアイデア、新たなビジネスチャンスにつながる。

<Caution>失敗事例：「多くの商品を見たい」という声を表面的に受け取り、トップページに商品を大量に並べたECサイト。読み込みが遅くなって離脱率が増え、どこを見ればいいか分からないという声が増え、購入率が下がった。真のペインは「適切な商品を素早く探したい」「自分に合った商品が見つかりづらい」だった。</Caution>

## プロセス：ペインから機会領域を導く

<Steps>
  <Step title="ペインを具体化する">ユーザーが何に困っているのかを具体的に書く</Step>
  <Step title="原因を洗い出す">「なぜ？」を繰り返し、ペインの発生理由を掘り下げる</Step>
  <Step title="隠れたニーズを仮説化する">ユーザーが本当に求めていることを推測する</Step>
  <Step title="機会領域を示す">隠れたニーズを満たすアイデアやソリューションを検討する</Step>
</Steps>

ペイン（具体的な問題や不満）→ インサイト（背景にある潜在的な欲求や価値観の洞察）→ 機会領域（新しい体験や既存の課題の大幅な改善につながるアイデアの領域）の順に考える。機会を探す視点は3つ。

<Cards>
  <Card label="機能的視点">求めている具体的な機能やサービス</Card>
  <Card label="情緒的・心理的視点">心情面のストレスや負担、楽しさや興奮</Card>
  <Card label="社会的視点">コミュニティや周囲の評価から生まれるペインや欲求</Card>
</Cards>

### 機会領域の優先度

判断の観点は、ユーザーにとっての重要度・緊急度、市場規模・ビジネスインパクト、自社の強みとのマッチ度、実現コスト・リスク（開発コスト、技術の難易度、法規制）の4つ。

| | 実現可能性 大 | 実現可能性 小 |
| --- | --- | --- |
| インパクト大 | 最優先で取り組む | 技術開発や調査を進めつつ中長期で検討 |
| インパクト小 | 短期的に改善しやすいが大きな成果は見込みにくい | 優先度は低い |

<Note title="目安">成功事例：クラウド会計サービスでは、数十名へのインタビューとテストで「最初のセットアップで挫折する人が多い」を最優先ペインに指定。5つあった初回登録のステップを3つに短縮し、難しい会計用語に説明を加えたチュートリアルを用意した。</Note>

## 見つけた後

<Figure src="/figures/n3-2-4-1501.webp" alt="ペインはゴールではなくスタート。1ペイン発見→2アイデア創出→3プロトタイプ作成→4検証→5改善と積み上げる" caption="ペインは見つけて終わりではなく、改善の出発点" />

- 大がかりなリリースより、小さく検証して改善を繰り返す
- ペインはチーム内だけでなく企業全体で共有できる形にまとめる。部署ごとにKPIが違うと、最重要のペインが伝わりにくい
- ペルソナやペインの優先度リストは定期的に更新し、関係者に周知する
- 活かし先は、既存プロダクトのUI/UX改善、新機能・新サービスのアイデア、マーケティング、ロードマップの優先度づけ
