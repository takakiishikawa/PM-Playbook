## 原則

- <Mark>**要件が不明確なままAIを使っても、的外れなプロトタイプが量産されるだけ。機能、ペルソナ、ユースケースを先に言語化する。**</Mark>
- AIの提案が「それっぽい」からとそのまま採用しない。独自性やブランドらしさ、細かなユーザーインサイトが失われる。
- AIは反復作業と大量のバリエーションを、人間は創造的な判断と微妙なニュアンスの調整を担う。

## デザインへの活用

<Steps>
  <Step title="要件を整理する">メイン機能は何か、どんなユーザーか、どんなユースケースを想定するか。ビジネス要件・技術要件と体験の流れを言語化する</Step>
  <Step title="生成する">ワイヤーフレームやUIプロトタイプをAIで作る</Step>
  <Step title="フィードバックで回す">素早く触り、各部署のレビューと簡単なユーザビリティテストで課題を出す。AIなら修正や再生成が容易なので、イテレーションを速く回す</Step>
</Steps>

### 注意点

| 注意点 | 内容 |
| --- | --- |
| 過剰な自動化への依存 | 必ず人間の視点で検証し、サービスのコンセプトに合うようカスタマイズする |
| ユーザーデータのバイアス | 特定の層に偏ったデータで学習していれば、提案もその層向けに偏る。新規ターゲットやグローバル展開では特に再考する |
| セキュリティと法的要件 | プライバシーポリシーの表示、Cookie同意、ログインのセキュリティなどが含まれていない可能性がある。最終責任はPMにある |

### ベストプラクティス

- 初期段階からユーザー課題を綿密に整理する。課題が明確なほどプロンプトの質が上がる
- フォント、カラー、ロゴなどのデザインガイドラインを、AIが使える形で用意する
- 少数の案に固執せず、複数パターンを素早く試作して比べる
- エンジニアに渡すときは、画面フロー図や機能要件ドキュメントをPMが責任をもって添える

## 要件定義への活用

生成AIは、こちらが考えていなかった角度からアイデアを提案してくれる。すべてが有用とは限らないが、アイデアの母数を増やす効果が大きい。

<Steps>
  <Step title="目的・ゴールを整理する">新機能のコンセプト出しか、既存機能の課題解決か、新サービスのアイデアか</Step>
  <Step title="現状の情報を渡す">調査データ、インタビュー結果、競合リサーチのサマリーなど</Step>
  <Step title="最初の質問を投げる">どんな課題があるか、考えられる解決策は、他社事例は</Step>
  <Step title="深掘りする">別の切り口で聞く、「なぜそう考えたのか」を聞く、アイデアを分類させる</Step>
  <Step title="評価して要件にする">優先度別に並べ、実現可能性とビジネスインパクトで要件にまとめる</Step>
</Steps>

| プロンプトのポイント | 例 |
| --- | --- |
| 文脈を詳しく伝える | 文脈がないと汎用的で表面的な答えしか返らない |
| フォーマットと制約を示す | 「表形式で」「3つ挙げ、それぞれメリット・デメリットを示して」 |
| フェーズを分けて聞く | 「まず現状の課題を整理して」「次に競合事例を」「最後に強みを活かすアイデアを3つ」 |
| ユーザーと目的を明示する | 「ユーザーは30〜40代の働く女性で時短ニーズが強い」「目的はオンボーディング改善で解約率を下げること」 |

### 発想を広げる使い方

- **仮想ブレスト**：チームでブレストする前に、AIに制約なしで大量に出させ、議論の土台にする。
- **強制発想法**：「旅行」と「リモートワーク管理」のように無関係な要素を組み合わせさせる。
- **常識を覆す視点**：あえて常識に反する発想を出させて着想を得る（実際に違法や倫理違反を推奨するわけではない）。
- **他業界の事例**：医療・教育・小売・金融などで似た課題を解いている事例を聞く。

## 共通の注意点

| リスク | 対策 |
| --- | --- |
| 機密情報の漏洩 | 入力が学習に使われる懸念がある。機微な情報はマスクする、社内専用やプライベートな環境を使う、データ利用ポリシーを確認する |
| 誤情報 | 生成AIは自信満々に誤った情報を出す。重要な情報は別の情報源で確かめ、AIの回答だけを根拠に判断しない |
| 多様性と偏見 | 学習データが特定の文化や言語圏に偏っていることがある。追加の調査や、異なる背景のメンバーのフィードバックで多面的に評価する |

## AI時代のPMの役割

- **プロンプトを設計する**：どう要件を伝えれば期待するアウトプットが得られるか。
- **データの品質を管理する**：信頼できるデータソースを選び、偏ったアウトプットにならないようにする。
- **選んで決める**：AIが生成した多数の案から、デザイン感覚と事業戦略の両方を踏まえて方向を定める。最終判断の責任はPMにある。
