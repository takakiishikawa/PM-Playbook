## 原則

- リスク管理を怠ると、後で発覚したときに行き当たりばったりの対策で負のループに入る。
- 対策に使った工数で元々のQCDSが圧迫され、遅延や品質低下につながる。
- 不確実性はプロジェクトの進行とともに減る。初期ほど丁寧に向き合う。

## リスクの種類

| 種類 | 例 |
| --- | --- |
| マイナスをもたらすリスク | 関連する外部サービスの停止、重要なメンバーの突然の退職、経営不振による予算の圧迫 |
| プラスになるリスク | 市場の風向きが自社事業に向く、有料の外部サービスが無料になる、メディアに取り上げられ課金ユーザーが増える |
| 特定し対策を検討できているリスク | 1週間後に外部APIがメンテナンスで止まる、来月エンジニアが1名退職する |
| 事前に対策できないリスク | 未知のウイルスの流行、法規制で自社サービスが規制される |

## 不確かさへの向き合い方

| 不確かさ | 対処 |
| --- | --- |
| 不確実性 | 情報を集める。複数の選択肢や結果に備える。レジリエンスを組み込む |
| 曖昧さ | 漸進的に解像度を上げる。実験、仮説検証、プロトタイプ |
| 複雑さ | システム思考、リフレーミング、プロセスベースで捉える |
| 変動性 | 代替案を見つけて評価し、予見して備える |
| リスクと機会 | 回避、エスカレーション、転嫁、軽減、受容 |

## プロセス：リスクを管理する

<Steps>
  <Step title="特定する">影響・要因・発生確率別に洗い出す。PMだけでなく技術者や経営層にもヒアリングする</Step>
  <Step title="対応を決める">発生確率と影響度で対応方針を決める</Step>
  <Step title="進行を管理する">対応計画を関係者に周知し、チーム全体で仕組みを作って検知する。検知できなければ対応が遅れる</Step>
</Steps>

| | 影響：低 | 影響：高 |
| --- | --- | --- |
| 発生確率：高 | 対策してリスクヘッジ | 対策を徹底し事前に阻止 |
| 発生確率：低 | 最小限の努力で様子見 | 発生時の対策を周知 |

| 対応 | 内容 |
| --- | --- |
| 回避 | 原因を取り除く |
| 軽減 | 発生率を低くする |
| 転嫁 | 第三者へ移す |
| 受容 | 受け入れて何もしない |

発生確率も影響も高いリスクは回避や軽減で根本的に起こらないようにし、どちらも低いリスクは受容してチーム内で認識だけしておく。

| リスク | 種別 | フェーズ | 影響 | 発生確率 | 方針 |
| --- | --- | --- | --- | --- | --- |
| APIサーバーの停止 | 外部影響 | 運用保守 | 高 | 中 | 回避・転嫁 |
| 本開発の予算がつかない | 予算管理 | PoC期間 | 低 | 低 | 受容 |
| 個人情報の流出 | セキュリティ | 進行中 | 高 | 低 | 回避・軽減 |

## よくある問題と対応策

| 要因 | 起きる問題 | 対応策 |
| --- | --- | --- |
| 不確実性（スキル不足） | 新技術に対応できない／設計漏れ／募集時点で認識がずれている | 研修に投資する／ペアプログラミングや相互レビュー／スキル要件を明確にして調達担当に共有する |
| 曖昧さ（コミュニケーション） | 作業内容が伝わらない／役割・権限が不明確／優先度が分からない | チケットの明文化とルール化、口頭文化をやめる／体制図の共通認識／定期的なふりかえりと部署間の共有 |
| 複雑さ（仕様の共有） | 仕様の考慮不足／システム警告の考慮漏れ／リリース判断ができない | 業務ドメインの勉強会／運用を含めたオペレーション設計／リリースの影響範囲を関係者とすり合わせる |
| 変動性（仕様変更） | テスト項目の更新漏れ／関係ない箇所のデグレ／他システムへの影響の考慮不足 | 確定仕様の明確化とテスト更新フロー／自動リグレッションテスト／ドメイン知識の共有とスコープ調整 |
| リスクと機会（トラブル対応） | 一次対応を誤り二次障害に発展 | 顧客対応フローの仕組み化、エスカレーションルールの共有と徹底 |

暗黙知を形式知にする仕組みが、曖昧さによるリスクを減らす（<NoteLink id="n7-6-2" />）。

## チェックポイント

- リスク対応がプロジェクトの制約条件（QCDS）の優先順位と整合しているか
- リスクの因果関係を理解し、対応する仕組みが作られているか
- 仕組みを使って好機を特定し、活用できているか
- 予防策によって、コストやスケジュールの予備を使わずに済んでいるか
