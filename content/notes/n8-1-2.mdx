## 原則

- <Mark>**クラウドでも、利用者が責任を持つ範囲がある。どこまでが自分たちの責任かを把握する。**</Mark>
- アクセス権は、ユーザーやアプリに必要最低限だけ与える（最小特権の原則）。
- ゼロトラストは、ネットワークの内側も含めて誰も信用しない前提で守る。

## 責任共有モデル

IaaS（例：AWS）の場合、クラウドそのもののセキュリティは提供者が責任を持つ。利用者は、その上に載せるものに責任を持つ。

| 責任を持つ側 | 範囲 |
| --- | --- |
| 利用者 | プラットフォーム、アプリケーション、IDとアクセス管理、OS、ネットワーク、ファイアウォールの構成 |
| 提供者 | クラウドの基盤そのもの |

<Note title="関連">IaaS・PaaS・SaaSで管理を分ける範囲は <NoteLink id="n5-2-4" /> を参照。</Note>

## 対策

| 対策 | 内容 |
| --- | --- |
| 最小特権の原則 | ユーザーやアプリのアクセス権を必要最低限に絞る |
| 分離とセグメント化 | データやシステムを適切にセグメントに分ける |
| セキュリティ意識の啓蒙 | 従業員やユーザーに教育やトレーニングを行う |
| 多要素認証 | 認証に複数の要素を使う |
| データ暗号化 | 保管時と転送時に暗号化し、漏洩時のリスクを下げる |
| ログイン監視 | ログイン試行の異常を監視し、不正アクセスを検知する |
| インシデント監視 | モニタリングで異常な傾向を検知する |
| 脅威情報の収集 | 脆弱性などの情報を集めて対応する |
| コンプライアンス | 対象となる法規制や規約に適合させる |
| 監査 | 外部の監査機関による監査を受ける |
| リスク評価 | セキュリティリスクを評価し、管理・対策する |

## セキュリティ技術

| 技術 | 役割 |
| --- | --- |
| ファイアウォール | ネットワーク上の通信を監視し、IPアドレスやポート番号のレベルで許可した通信だけを通す |
| WAF | Webアプリケーションへの不正なリクエストを検知・防御する。SQLインジェクションやXSSなど、脆弱性を突く攻撃を防ぐ |
| IDS（侵入検知システム） | 通信やシステムのログを監視し、不正を検知する |
| IPS（侵入防止システム） | IDSの機能に加え、不正なアクティビティを自動的に遮断する |
| エンドポイントセキュリティ | パソコンやスマートフォンなど、利用者のデバイスでの対策 |

## ゼロトラスト

誰も信用しないという考え方に基づくセキュリティモデル。

- ネットワーク内のすべてのアクセス要求をデフォルトで拒否する
- 必要なユーザーやデバイスを特定し、最小限のアクセス権だけを与える
- ネットワーク内の不正アクセスや攻撃を防ぎやすく、従来のセキュリティで見過ごされがちな内部の脅威にも対処できる
