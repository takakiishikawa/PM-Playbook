## 原則

- 妄想で意思決定してはいけない。今できる限りファクトを集めたうえで決断する。
- 不確かさと上手に向き合うことがPMに求められる。
- 意思決定の遅れは、スケジュール遅延・コスト超過・品質低下の確率を高める。決めることで、やりたいことが実現できる。

## PMが決めること

1. 課題
2. ユーザー
3. 解決策
4. プロダクトビジョン
5. プロダクト戦略
6. 中長期ロードマップ

ほかにも、課題の優先順位づけ、開発の優先順位づけ、開発リソースの配分、プロダクトの品質管理など、意思決定の種類は非常に多い。

## 意思決定が難しい理由

| 理由 | 内容 |
| --- | --- |
| 情報が不完全 | ファクトを集めきれないことも多く、不完全な情報からリスクを考えて決める |
| 時間が限られている | プロダクトを成長させるためにかけられる時間には常に限りがある |
| マーケットの変化が激しい | 課題を解決できても、課題そのものが変わることがある |
| リソースに限りがある | 開発工数もお金も限られる中で、最大の効果を出す |

<Note title="目安">意思決定に求める確からしさの目安は、アソシエイト〜ジュニアPMで5割、ミドル〜シニアPMで7割、VPoP以上で8割以上。</Note>

## プロセス：意思決定の7ステップ

<Steps>
  <Step title="対象を特定する">何を決めるのかを明確にする</Step>
  <Step title="情報を集める">関連する情報を収集する</Step>
  <Step title="代案を特定する">取りうる選択肢を挙げる</Step>
  <Step title="エビデンスを検討する">各選択肢の根拠を比べる</Step>
  <Step title="選ぶ">選択肢の中から選ぶ</Step>
  <Step title="行動に移す">選んだ案を実行する</Step>
  <Step title="見直す">結果を確かめ、必要なら決め直す</Step>
</Steps>

| ステップ | 例：パーティーの開催方法 |
| --- | --- |
| 対象を特定する | パーティーの開催方法 |
| 情報を集める | 都内で良い会場が見つからない。遠方で現地参加できない人がいる |
| 代案を特定する | Zoomのオンラインパーティー |
| エビデンスを検討する | 過去のZoomイベントは参加満足度が高かった |
| 選ぶ | Zoomは無料だと40分の制限がある。DiscordやMeetもある |
| 行動に移す | Discordでのパーティーを企画して案内を送る |
| 見直す | Discordが初めてのメンバーも無事にインストールでき、この方法で開催を決定 |
