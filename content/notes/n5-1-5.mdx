## 原則

- <Mark>**レビューは「プロダクト → 意図や目的 → デザイン」の順。目的を共有せずにデザインから見ない。**</Mark>
- ユーザー視点を主観（個人の感想）より優先する。
- 指摘の反映は一つずつ。一度に全部変えない。

## 2つの視点を行き来する

| 視点 | 見るもの |
| --- | --- |
| フロー | 複数画面の遷移を通した体験。目的に辿り着きやすいか |
| 画面 | 1画面内の要素の配置や詳細 |

## プロセス：レビューする

<Steps>
  <Step title="目的と意図を共有する">何のプロダクトで、この画面で何を実現したいのか</Step>
  <Step title="ユーザーを確かめる">ペルソナは誰か、普段どんなプロダクトを使っているか、第一印象はどうか、ペインは何で、このデザインで解決されるか</Step>
  <Step title="原則に照らして見る">デザインの原則とレイアウトの4原則で確認する</Step>
  <Step title="全体を確認する">迷わず使えそうか。普段使っているものと比べて使いにくい差はないか</Step>
</Steps>

## 確認項目

| 原則 | 問い |
| --- | --- |
| 可視性 | 現在の状態と、次に求められる行動が分かるか |
| フィードバック | 行動に対して情報が返り、状態や操作の完了が示されているか |
| アフォーダンス | ボタン・リンク・入力欄が、触れる要素だと明確に分かるか |
| マッピング | 情報の関係性が視覚的に理解できるか |
| 制約 | 選択肢を減らし、不要な操作や誤操作を防ぐ仕組みがあるか |
| 統一感 | ブランド要素、UI、プロダクト外（メール・通知など）まで一貫しているか |
| 近接 | 関連情報はまとまり、異なる情報は離れているか。要素は多すぎないか |
| 整列 | 基本は左寄せか。見えない線がそろい、凸凹がないか |
| コントラスト | 欲しいアクションが明確か。強調は3段階程度で、色は重要なところだけか |
