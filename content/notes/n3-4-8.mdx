## 原則

- <Mark>**アンケートの項目を作るには仮説が必要。仮説がないアンケートは余計な質問が増え、回答率が下がる。**</Mark>
- アンケートは「目的が8割」。ゴールが決まっていれば、必要な質問と不要な質問を取捨選択でき、集めるデータの粒度も決まる。
- アンケートで情報を集め、ユーザーヒアリングで深掘りする。「なぜ起きたのか」はアンケートでは分からない。

## アンケートとは

集計結果を数値データにして実態を把握し、仮説の構築と検証をする定量調査。最も身近で、最も扱いにコツがいる課題特定の方法。定性調査は体験を知るもの、定量調査はファクトを知るもの。

| 種類 | 目的 | 使用例 |
| --- | --- | --- |
| リサーチアンケート | マーケットの状況やニーズの変化・トレンドを知る | 業界調査レポート、会社のPR |
| ニーズ調査アンケート | ニーズ（誰のどんな課題）があるかの仮説を検証する | 新規プロダクト開発、自社プロダクトの改善 |
| フィードバックアンケート | リリースした機能がどれくらい課題解決できているか、満足されているかを調べる | NPS、満足度調査 |
| アクセプタンスアンケート | ソフトウェアが要求を満たしているかを確かめる（受け入れテストの一環） | 制作会社がソフトウェアを納品するとき |

| タイミング | 目的 | 使う種類 |
| --- | --- | --- |
| 機能開発の前 | ファクト集め、仮説検証 | リサーチ、ニーズ調査 |
| 機能開発の後 | 満足度調査、次の開発方針の決定 | フィードバック、ニーズ調査 |

## よくある失敗

| 失敗 | 理由 |
| --- | --- |
| なんとなく身近な人にとってみる | 目的によって、誰に何を聞くかは大きく変わる |
| SNSの投稿やコメントでニーズがあると判断する | SNSはフィードバックにはなるが、ニーズ調査として使うのは危険 |
| ギフト券などをお礼に渡す | 回答するべきでない人が、ギフト券目当てで回答する |
| NPSの結果をもとに機能開発を行う | NPSが高いから優れているとは限らない。ヒアリングでの深掘りが大事 |
| わずかな人数にしか実施しない | 定量調査なので、実施数が多いほど正確になる |
| ゴールが抽象的すぎる | 「顧客満足度を知りたい」ではなく「NPSで把握する」「5段階で評価する」と指標を決める |
| ゴールを欲張りすぎる | 各部署の要望を全部入れると設問が膨れ、回収率が下がる。目的を1〜2つに絞るか、フェーズを分ける |
| ゴールが共有されていない | 後出しのリクエストが出る。初期にゴールを資料にまとめて合意する |

## プロセス：目的とゴールを決める

<Steps>
  <Step title="背景を把握する">なぜこの調査をするのか。解決したい課題、知りたい情報、対象ユーザー層を確かめる</Step>
  <Step title="ゴールの仮説を立てる">「新機能を使わなくなる理由トップ3を明確にする」のように、できるだけ定量的な指標を含める</Step>
  <Step title="関係者と合意する">背景と重要性、達成したときのメリット、質問の叩き台を示してフィードバックをもらう。不要な質問はカットする勇気を持つ</Step>
  <Step title="ゴールを言葉で定義する">「新機能の利用理由・離脱理由を把握し、UX改善策を3つ提案できるデータを集める」</Step>
</Steps>

<Note title="目安">目的を具体化するには、現状を整理する → 理想像（例：80%以上の顧客が満足と回答する）を描く → ギャップから課題を洗い出す → 「この情報が得られれば意思決定に役立つ」という形に落とし込む。5W1H（なぜ・何を・誰に・いつ・どこで・どうやって）で抜け漏れを確かめ、KGI・KPIツリーで「どの数字を動かすための調査か」を明確にする。</Note>

### ゴール設定で意識すること

- ビジネス視点とユーザー視点の両立：回答時間、興味を持てる設問か、ユーザーにもメリットがあるか。質問が多すぎたりプライバシーに踏み込みすぎたりすると回答率が下がる
- 定量と定性の両面：NPSを集めるなら、その理由を聞く記述式も用意する
- 分析とレポートまで想定する：クロス集計、テキストマイニング、経営層向けの1ページサマリなど、使い方を先にシミュレーションする
- 冒頭で目的を伝える：「新商品の改善とサービス向上のために行い、機能拡充や価格の見直しに役立てます」のように、データの使い道と回答者のメリットを示す

## 対象ユーザーとサンプリング

対象を限定しないと、どの層にも支持されない平均的な結果になる。目的・課題の明確化 → マーケット全体の把握とセグメンテーション → 優先セグメントの選定 → ペルソナ化 → リクルーティングの順に進める。

| セグメンテーション | 要素 |
| --- | --- |
| デモグラフィック | 年齢、性別、職業、所得、居住地域 |
| サイコグラフィック | 価値観、ライフスタイル、興味・関心 |
| 行動 | 利用頻度、ブランドロイヤルティ、利用状況 |
| テクノグラフィック | 保有デバイス、ネット利用習慣、SNS利用 |

優先するセグメントは、ビジネスインパクト、リーチのしやすさ、緊急性、今後の成長可能性で選ぶ。既存顧客の離脱防止なら主要顧客層、新規開拓なら潜在ユーザー層を優先する。

| | 確率的サンプリング | 非確率的サンプリング |
| --- | --- | --- |
| 手法 | 単純無作為抽出、系統抽出、層化抽出、多段抽出 | 割当法、有意抽出、便宜抽出、スノーボール |
| 向いている調査 | 定量調査。統計的に母集団を推定し、全体像を把握する | 定性調査。「知りたい行動や思考を持つ人」を意図的に選ぶ |

### サンプルサイズ

| 調査 | 目安 |
| --- | --- |
| 定量（アンケート） | 95%の信頼度で誤差±5%に収めるなら、約385〜400人 |
| 定性（インタビュー・ユーザーテスト） | 5〜10人程度。5〜8名を1グループにして複数グループに分けることも多い |

定性調査は人数より、新しい知見が出なくなる「サチュレーション（飽和）」を基準に繰り返す。新しいインサイトが出ない、似た回答が増える、仮説を覆す情報が出ない状態になったら止める。重要なセグメントが足りなければ追加する。

<Note title="補足">「インタビューで仮説を見つけ、アンケートで定量検証する」「アンケートの行動意向をアクセス解析の実際の行動で裏付ける」のように、複数の手法を組み合わせる（トライアングレーション）。</Note>

### 注意するバイアス

| バイアス | 内容 |
| --- | --- |
| 自己選択バイアス | 自ら応募した人は、強い関心や強い不満を持つ極端な層に偏る |
| サンプルバイアス | 募集経路が偏り、特定の属性ばかり集まる |
| 観察者バイアス | 調査する側の先入観で、誘導的な質問や解釈の歪みが起きる |
| 社会的望ましさバイアス | 「自分をよく見せたい」心理で、実際と異なる回答をする |

対策は、募集経路を複数にする、スクリーニングで属性のバランスを確かめる、ニュートラルな言い方をする、十分なサンプル数を確保する、結果を総合的に分析すること。

## 質問形式

| 形式 | メリット | デメリット | 設計のポイント |
| --- | --- | --- | --- |
| 単一回答 | 負担が少なく、集計しやすい | 選択肢が少ないと実態を取りこぼす | 選択肢の網羅性と排他性、数、「その他」の有無 |
| 複数回答 | 状況を幅広くカバーできる | 組み合わせの分析が手間。「とりあえず全部」が増える | 推奨回答数を示し、集計方法を先に決める |
| 段階評価（リッカート尺度） | 印象を定量化でき、平均や中央値で比べやすい | 中間値が多いと傾向が出ない。人によって基準が違う | 段階数とラベルを明確にし、「どちらとも言えない」を設けるか決める |
| 自由記述 | 生の声や本音、本質的な課題をつかめる | 分析が煩雑。白紙や短文のリスク | 位置と数を絞り、例を示し、分析体制を整えてから入れる |
| 数値入力 | 平均や分散をそのまま計算できる | 入力ミスや極端な値が混じる | フォーマット、範囲、単位を明示する |

選択式と自由記述のハイブリッド（「その他」を選んだ人にだけ記述欄を出す）や、行動ログとの照合を前提にした設計もある。

<Note title="目安">流れは「基本情報を単一回答 → 評価を段階評価 → 具体的な意見を自由記述」。スマホで答える人が多いならタップで答えられる形式にし、長い記述は避ける。全体は5分以内で答えられる量にする。</Note>

## 設問の注意点

- 中立的に聞く：「不満な点は何ですか？」ではなく「気になる点や改善が必要だと感じる点はありますか？」
- 専門用語や難しい言葉を避け、回答者に合わせた語彙にする
- 選択肢は網羅的かつ排他的に：「20〜29歳」「29〜39歳」は29歳が重複する。並びは時系列・数値順など分かりやすく
- 重複・類似の質問を減らす。同じことを2回聞くなら、前後比較のように狙いを明確にする
- 絶対に知りたい質問を前に、優先度の低い質問や自由記述を後ろに置く。条件分岐（スキップロジック）で不要な設問を出さない
- 1つの設問に内容を詰め込みすぎず、分割する
- 本配信の前に小規模なテストで、答えにくい質問・あいまいな選択肢・所要時間を確かめる

<Caution>個人情報は可能な限り匿名で集め、必要な場合だけ利用目的と管理方法を明記して聞く。人種・民族・宗教・性的指向などセンシティブな項目は慎重に扱い、聞く場合も意図を示して任意回答にする。個人情報保護法などの法令と社内規程を守る。</Caution>
