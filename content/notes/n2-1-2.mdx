## 原則

- ノーススター指標は、組織やチームが同じ方向を向くための拠り所。プロダクトが長期的に目指す価値、ユーザーが得られる根源的なメリットを言語化したもの。
- 財務指標ではない。あくまでユーザー価値をベースに考える。
- 設定して終わりではなく、そこからがはじまり。迷ったら「我々が実現したい価値は何か」に立ち返る。

## なぜ重要か

日々の意思決定は膨大になる。毎回ゼロから考えていると、意見が分かれたり場当たり的な判断に流されたりする。ノーススター指標を**すべての判断基準**として据えておけば、一貫した行動を取りやすく、部門間の連携もスムーズになる。

## KPI・OKRとの違い

| 種類 | 特徴 | 時間軸 | 目的 |
| --- | --- | --- | --- |
| ノーススター指標 | 理想的に実現したい価値の核 | 長期的 | 組織の方向性を示す |
| KPI | 成果を定量化した指標 | 短・中期的 | 成果管理 |
| OKR | 目標と成果指標のフレームワーク | 四半期・年間 | 目標設定と達成度管理 |

- KPIは部門ごとに異なる指標を設定でき、短期的な成果を測る。ノーススター指標は組織全体で共有する単一の指標で、売上やPVとイコールになるとは限らない。
- OKRの最上位のObjectiveに近い概念。ノーススター指標が明確なら、OKRも設定しやすく、各チームが納得感を持って運用できる。

## 果たす役割

| 役割 | 内容 |
| --- | --- |
| 共通言語・共通認識 | 背景の異なるメンバーが同じ方向を志向し、「指標に照らしてプラスか」で判断できる |
| 優先順位の明確化 | 「指標を最大化するにはどの施策が最も効果的か」に立ち返ることで、優先順位をつけやすくなる |
| 長期的視点での成果追求 | 短期的に結果が出なくても、指標のための取り組みなら確信を持って投資できる。近視眼的な意思決定を避けられる |

## 具体例

| プロダクト | 価値 | 重視する指標 |
| --- | --- | --- |
| Spotify | 音楽を通じた新しい発見 | レコメンドで新しい曲を聴いた回数、友達と音楽をシェアした回数 |
| Facebook | 人と人を繋ぐ | 友達数、1日のアクティブユーザー数 |
| クックパッド | 日々の料理が楽しくなる | 実際に料理を作った人数、リピート率 |

## 良いノーススター指標の条件

1. ユーザーにとって価値がある状態を表している
2. 中長期的な視点で追える
3. 組織のすべての意思決定を促す「道しるべ」になりうる
4. 測定が可能、または測定プロセスを作れる
5. 組織やプロダクトの独自性を表している

<Caution>抽象的すぎると、誰も追わなくなる。数値化できなくても、定性的にモニタリングできる仕組みを整える。</Caution>

## プロセス：設定する

<Steps>
  <Step title="ビジョン・ミッションを再確認する">何のためにこのプロダクトを提供しているのか、どんな価値を届けたいのかをチーム全員で言語化する</Step>
  <Step title="ユーザーにとっての核心的価値を特定する">使うことで何が得られるのか。顧客が本当に得たい価値にフォーカスする</Step>
  <Step title="具体的な行動・状態を洗い出す">「毎日使うようになった」「友人に紹介している」など、価値を得ている状態を挙げ、測定可能なポイントを見つける</Step>
  <Step title="最も象徴的な指標を1〜2つに絞る">多すぎると何を重視すべきか分からなくなる。多くても2つ程度がベスト</Step>
  <Step title="合意を得て浸透させる">疑問や不安を解消しながら最終決定し、目標設定のたびに必ず確認する文化をつくる</Step>
  <Step title="定期的に振り返る">フェーズや方向性が変われば、指標のアップデートも検討する</Step>
</Steps>

## 運用のポイント

| 項目 | 内容 |
| --- | --- |
| 短期KPIとのバランス | 対立する場面では関係性を説明し、最終的には指標に回帰する仕組みを作る |
| 施策の「ふるい」に使う | 指標を高める効果が薄いと分かったら、施策をやめる決断も重要 |
| 可視化と共有 | ダッシュボードや定例の議題に組み込み、達成度と使われ方を見えるようにする |
| ユーザー理解の更新 | ニーズが変われば指標は陳腐化する。インタビューやデータ分析で妥当性を確かめ続ける |
| 柔軟な変更を恐れない | 最初の指標に固執せず、今の状況に合っているかを問い続ける |

## よくある誤解

| 誤解 | 実際 |
| --- | --- |
| 財務指標を追えばよい | 自社の利益を優先するとユーザーが離れ、長期的には売上も下がる |
| ワンフレーズのビジョンで十分 | 測定可能な形、具体的な行動や状態の定義まで踏み込む |
| 指標は絶対 | 組織のコンパスであって、KPIや現場の肌感覚、アイデアも無視しない |
| 一度決めたら変わらない | 黎明期は登録ユーザー数、ユーザーが増えたらエンゲージメント、とフェーズで変わる |

## チームでの使い方

役割ごとに、指標に向けた問いを持つ。

| 役割 | 問い |
| --- | --- |
| エンジニア | どういう機能を作れば指標が高まるか |
| PM | どの機能や改善が最も指標向上に貢献するか |
| UI/UXデザイナー | どういうデザインが指標を支えているか |
| マーケティング | どう価値を伝え、行動を促すか |

日々の小さな施策を「届けたい価値に近づいているか」で評価できるため、成功を称えるときも失敗から学ぶときも、建設的に話し合う土台になる。

## プロダクト別の設定例

| 種類 | 指標の例 |
| --- | --- |
| ECサイト | リピート購入率、顧客生涯価値（LTV） |
| SaaS | MAU、ユーザーあたりの機能利用回数、継続利用率 |
| コミュニティ・SNS | ユーザー間の交流回数、投稿数、コメント数 |
| 教育サービス | コース完了率、学習後のスキル活用度、資格取得率 |
| 健康・フィットネス | 継続利用日数、健康目標達成率、生活習慣の改善度 |
